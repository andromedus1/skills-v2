# Decomposing and coordinating a methodology review

Use this reference when selecting a split, delegating a component review, or
resuming a review with children. The main skill owns the common review protocol,
authority and exit outcomes; this reference supplies coordination at any scale.

## Contents

- [Integrate at the parent](#integrate-at-the-parent)

## Choose boundaries

Start from the charter's decisions and outcomes. Identify methodological questions,
assumptions, shared constraints and scenarios that connect them. Compare an unsplit
review with useful alternative cuts by decisions, scenarios or components. Record
why the chosen cut helps, what it excludes and what coupling remains. Do not impose
a fixed candidate quota here or copy ARD's research decomposition procedure.

Use the main skill's selector. Distinct evidence domains alone do not justify child
methodology reviews: one decision may simply need a multi-facet research campaign.
Create children when their own comparison and assessment contributes a distinct
answer to the parent. Coordinated children can share one policy decision: each
returns a scoped methodology assessment even though adoption is adjudicated together.
Independent policy adoption is a program distinction, not a prerequisite for every
child. Keep mutually dependent decisions together; use explicit
dependencies between independently assessable decisions. Shared questions have
one owner whose results others reference, not repeated investigations.

If the boundary cannot yet be chosen, state the uncertainty. Ask the operator when
intent or constraints are missing; otherwise commission bounded discovery for the
specific evidence gap. Do not start an exhaustive review to discover its scope.
An explicit operator shape is a constraint to honor where feasible, not a reason
to conceal lost coverage. Surface any consequential mismatch.

Repeat the selector within a child only if scope shrinks and a new comparison has
decision value. Children may use different shapes and research depths. Stop
splitting when the questions are sufficiently bounded, evidence already settles
them, further cuts add no distinct decision, or agreed limits are reached. Preserve
uncovered questions in the record; do not label them reviewed.

## Run a child review

Use the existing record locations from [review-record.md](review-record.md).
Named sections in one controller suffice for a coordinated review. If a program
needs independently scheduled review items, use the project's existing workflow
to create them and link their authoritative records from the root. Every child
record links back to its root record and parent so resume restores the shared limit. Review
controllers have no `research` tag/dials. Research commissioning items remain
separate. Without a work substrate, use linked sections in the existing fallback
record; do not create a new tracker or research tier.

Pass this skill and reference to a child worker, together with:

| Input | Required content |
| --- | --- |
| Identity and purpose | Root/child IDs and record links, parent question, covered questions and expected contribution |
| Charter | Baseline, scope/exclusions, outcomes, criteria/scenarios and inherited constraints |
| Evidence | Relevant current artifacts and known gaps; source verification remains with Agentic Research |
| Coordination | Dependencies, shared-question owner, root round/limit and allocated next checkpoint |
| Authority | Actual operator decisions and authorized actions; questions that still require adjudication |
| Return location | Existing record section/item and the parent that consumes it |

Delegate only independent work whose coordination is useful; an inline child can
use the same contract. A child repeats the common protocol for its assigned scope;
coordinated children return assessments for their parent's combined decision.
It may propose a smaller cut within that scope but cannot enlarge its charter,
reset limits, authorize changes, or rewrite a sibling's decisions. Batch related
operator questions through the parent where useful. Reuse applicable authorization
rather than asking the operator to approve the same action twice.

Each child returns a dated assessment with:

- Scope, baseline and actual coverage, including excluded or unavailable areas.
- Stable findings with evidence references, uncertainty, contrary evidence and
  implications for the parent or siblings.
- Relevant verified research outputs and any unresolved evidence requests.
- Actual operator decisions and authorized actions, separate from recommendations.
- Remedy state and remaining obligations; the next dependency/checkpoint.
- An existing exit outcome for the child scope and its reason.

Before an assessment has run, return a checkpoint with no outcome yet, outstanding
steps and the next action. Do not label an ordinary in-progress checkpoint incomplete.
Qualify new finding IDs by their originating review ID, such as `R4-B/METH-003`.
For existing bare IDs, preserve the ID and use its owning review ID when matching
or emitting work. Never merge findings merely because local numbers match. Retain
origin identities across re-cutting; record aliases/merged IDs for actual duplicates.

An assessment handoff is not a clean exit. A child with decisions or remedies
pending returns that status. Its research engagement completing changes neither
the child nor parent's methodological verdict by itself.

## Integrate at the parent

Read the children's actual assessments and their evidence, not just verdict labels.
Check coverage against the parent charter, deduplicate findings with retained IDs,
and expose contradictory recommendations. Test common scenarios across child
boundaries: individually sound methods can conflict when combined or leave a gap.

Separate operational integration from research synthesis. The parent records
coverage, decision dependencies, remedy state and the whole-scope assessment.
Commission new cross-source analytical synthesis through Agentic Research, with
research-program coordination only when its separate engagements warrant it.
Child analyses are lenses; conclusions must still trace to source attestations.
New external claims raised during integration remain provisional until verified.

The fresh parent assessor receives the charter, current baseline, child coverage
and assessments, verified research, common scenarios and exact operator decisions.
It must examine interactions, persistent/retained risks and new findings. Do not
prescribe a verdict or treat all children passing as parent success. A single fresh
assessment may cover multiple levels only when its documented inputs and coverage
satisfy every level; no duplicate pass is needed just to match a diagram.

## Rounds, stopping and resume

The root owns the agreed limit and count of complete assessment rounds. When
selecting a program, check whether the limit fits its expected independent change
cycles; explain any material mismatch and request an adjustment only when needed.
Keep an already agreed limit unless the operator changes it.

Record the in-progress root round and allocated child checkpoints before dispatch.
A program child may complete decision → authorized change → child-scope reassessment
on its own schedule, as its one cycle for that root round. It need not wait for a
sibling's decision. Coordinated children contribute to the parent's combined cycle.
Do not start another cycle for a child within the same root round.

The fresh parent assessment closes a round by evaluating the whole charter using
returned child checkpoints, available verified evidence and explicit gaps. Waiting
children report their exact status; do not wait for every child to be clean or
claim missing coverage was assessed. Count this completed assessment even when its
outcome is pending or incomplete. A checkpoint without that assessment is not a
completed round. Carry pending work into the next allocation without restarting
it or granting extra cycles. Research verification corrections remain governed by
the research engine's own contract; no nested remediation loop bypasses the root limit.

Creating, splitting, re-cutting, resuming or moving a review into a program does
not reset its round allowance. Preserve coverage and finding IDs when boundaries
change. If a child is blocked, return its exact awaiting/incomplete outcome and
continue independent authorized work. A pending checkpoint is not permission to
repeat unchanged child work indefinitely.

Before another round, identify changed evidence, an authorized change or an
operator decision that permits progress. Reuse unaffected child assessments whose
baseline and coverage remain valid; re-evaluate affected children and interactions.
At the limit, use the main skill's existing exit precedence and surface unfinished
coverage. Only the operator can extend the limit; do not lower severity or silently
exclude a branch to report convergence.

On resume, read the root record first, then the relevant authoritative child records.
Restore the charter/baseline, chosen cut, shared-question ownership, dependencies,
round/checkpoints, findings, decisions and pending remedies. Compare intervening
changes and identify the next unfulfilled step. Do not repeat satisfied research or
adjudication without a named freshness/coverage gap or changed decision context.
An archived child may need its full report recovered through retention conventions;
a terminal work-item stage alone cannot substitute for that report.
