# Agentic Research: fixes from the methodology-review pilot

## Brief

This feature fixes the `agentic-research` defects found during the project-blueprint
Knowledge pilot of `research-pipeline:methodology-review`. The full findings are in
`feature-methodology-review-pilot-learnings` under "Pilot findings". Andrew split
this work out on 2026-10-20 (that item's design decision 5): it changes a separate
plugin and ships in its own PR. `feature-methodology-review-pilot-learnings`
depends on this feature, because F21 and F27 affect the gates of the strategy
research that feature commissions.

Findings in scope:

- **F21 (M). Rigor table vs `evaluate` reachability.** The research-orchestrator
  rigor table shows `evaluate` only at `full`. The reachability rule says
  `evaluate` re-enters the floor of any cross-specialist synthesis. A host that
  followed the table skipped `evaluate` and closed early. Make the table and the
  rule agree.
- **F27 (M). Bare citations pass lint silently.** `lint-citations.py` reported
  "0 resolved · 0 broken" for a brief with 207 bare `{N}` citations, which looks
  clean but checked nothing. Flag bare numeric citations, or resolve them
  through `references.md`.
- **F16. Short-handle citations.** One specialist cited short handles and
  produced 160 broken chains. The specialist role brief should state the
  full-handle citation form.
- **F17. Lint depends on the working directory.** Lint resolves `source_path`
  relative to the working directory, so running it from `.research/` gives false
  `unreachable-source` findings.
- **F8. No concurrency rule for the bibliography.** Parallel specialists share
  one append-only numbered `references.md`. The pilot host reserved number
  blocks and merged per-specialist refs files afterwards. Specify one rule.
- **F15. Discipline inlining is costly.** The verbatim discipline bundle plus
  role brief was inlined into 9 dispatches. Consider a read-the-file handshake
  with a content-hash echo, keeping the same discipline guarantees.
- **F24. No option to delegate a single facet.** The light path (one facet)
  requires the host to author inline. Add a "single delegated specialist"
  option: the same discipline inlining and gates, no cross-synthesis, so
  `evaluate` stays unreachable.

Surfaces involved: `skills/research-orchestrator/` (SKILL.md and references),
`skills/research-discipline/`, and `ard-core/kernel/lint-citations.py` with its
conformance fixtures. Validate both the Claude and Codex plugin shapes. Bumping
agentic-research needs the "Build research-view binaries" workflow.

## Simplification opportunity

- F15 may replace repeated verbatim inlining with one file reference plus a hash
  echo.
- F21 should resolve to a single source of truth for reachability, rather than a
  table and a rule that can drift apart.
- Retain every ARD invariant: the anti-fabrication floor, the verification stack
  and the FR.1 evaluator isolation.

## Design decisions

Resolved with judgment under autopilot (2026-10-20). Priority order: ARD SPEC,
then the simpler option, then the reversible one.

- **F21: align the skill with SPEC §3.1/§7, and leave SPEC unchanged.** SPEC
  already says a cross-specialist synthesis puts `evaluate` back in the floor.
  It also says the profiles form an ascending chain, because `evaluate` is
  reachable only where `adversarial-read` is already in the floor. So any
  multi-path walk fires both gates at every rigor label. The skill's table and
  walk line were the drift.
- **F27: a new broken chain status, `bare-citation`.** The status is high
  severity and is added to CATALOGS §3, with `catalogs.json` regenerated by
  `tools/gen-contract.py`. A bare `{N}` cannot enter the chain, so it belongs
  with the other broken statuses, not with the warn-only pattern categories. The
  lint does not resolve `{N}` through `references.md`: number-to-bibliography
  correspondence is deployment-mapped (CATALOGS §3, check 7), and flagging the
  citation is what closes the silent-pass hole.
- **F17: resolve against the project root, keeping a cwd fallback.** A relative
  `source_path` resolves against the project root. That root is `--project-root`
  when given; otherwise the parent of the nearest `.research` ancestor of the
  attestation dir. The current working directory remains a fallback, so no
  existing invocation regresses.
- **F15: a read handshake as an alternative propagation mechanism.** SPEC §5
  leaves the mechanism to the deployment ("any host-native context propagation
  that guarantees the content arrives"). When the sub-agent can read the
  repository:
  - the dispatch carries the bundle's path and the lead's sha256 of it, instead
    of the text;
  - the sub-agent reads the file in full before engaging sources, and echoes
    `discipline-sha256: <hash>` as the first line of its return;
  - a missing or mismatched echo voids that dispatch's output, which is then
    re-dispatched with the bundle inlined.

  Verbatim inlining stays the fallback, used whenever the sub-agent cannot read
  the repository. Residual risk: the echo proves version and access, not
  attention. Inlining carries the same residual, so the guarantee is
  equivalent. No marker file and no new validator.
- **F8: the lead reserves a number block for each specialist.** At dispatch, the
  lead gives each specialist a disjoint `{N}` block above the current
  `references.md` maximum. Each specialist writes its entries to
  `specialists/<facet>.refs.md` and never edits `references.md`. The lead
  appends them, in block order, after the specialists return and before lint.
  Unused numbers inside a block stay as gaps, since the file is append-only and
  never renumbered. This is the procedure that worked in the pilot.
- **F16: citation form is stated in the specialist brief.** The handle is the
  attestation's full `source_handle` (its filename stem), never shortened. The
  specialist lints its own brief before returning.
- **F24: a single delegated specialist path.** The light path gains a variant:
  one facet, dispatched to one research specialist under the same dispatch
  composition. The specialist writes its brief directly to
  `analysis/briefs/<slug>.md`. There is no cross-synthesis, so `evaluate` stays
  unreachable, and the lead runs lint, the rigor-selected `adversarial-read` and
  `spot-check`.

## Implementation notes

Two decisions were added during implementation, both by judgment:

- **The evaluator always gets the bundle inlined.** Its FR.1 isolation is enforced
  by what it is handed. A read handshake would make it open repository files,
  where the briefs and attestations also live. Only the specialist and the
  adversarial reader may use the handshake.
- **The bare-citation fence is scoped to claim-bearing artifacts.** These are
  artifacts with provenance `agent-synthesis` or `agent-authored-from-raw`, or
  with none declared. Linting this repo's corpus found 44 bare `{N}`, all in
  `agent-verification` records (a campaign evaluation and a checklist) that
  refer to the synthesis's own numbering. Those are not sourced claims. After
  scoping, the corpus has 0 hits. A conformance negative covers the scope rule.

## Risks

- **Reading the multi-path rule as "always full".** This could seem to raise
  cost. It is what SPEC already requires, and Andrew prefers thoroughness.
  **Fallback:** none needed. Name it in the PR so the semantics are visible.
- **The bare-citation regex over-matching.** It could fire on templating or
  JSON in prose. **Fallback:** code and inline-code masks, a `$` lookbehind and
  conformance negatives.
